Installation

Pick the option that fits your workflow.

NuGet (nuget.org)

Use this if the package is published on nuget.org.

dotnet add package 8Bitiz.RedirectManager

Your own NuGet server (Docker)

Run BaGet in Docker, push the plugin, then add your feed and install in any project.

docker compose -f docker/docker-compose.yml up -d
./scripts/push-to-feed.sh

In your Umbraco project: add the feed to nuget.config, then dotnet add package 8Bitiz.RedirectManager.

Local feed

Build the plugin repo, then point your project’s nuget.config at the build output folder.

dotnet build -c Release
# In your project: add feed path, then:
dotnet add package 8Bitiz.RedirectManager

Usage

  1. Install the package and build your Umbraco project.
  2. Open the backoffice → Settings → Redirect Manager.
  3. Add a redirect: Old URL, New URL (for 301/302), status code, optional notes. Use regex if needed.
  4. Use filters and search, export/import CSV, or run “Test” on a path to see which rule matches.

Status codes

Each redirect can return a different HTTP response.

Code Name When to use
301 Permanent Redirect Page has permanently moved. Search engines transfer link equity to the new URL.
302 Temporary Redirect Page has temporarily moved. Use for A/B tests or short-term moves.
404 Not Found Return 404 for a specific path (e.g. deprecated URL that should not redirect).
410 Gone Resource is permanently gone. Tells crawlers to drop the URL from the index.
