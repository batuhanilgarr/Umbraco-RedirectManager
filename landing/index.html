Everything you need for redirects

Built for Umbraco 13, 17 & 18. Install, open Settings → Redirect Manager, and start adding rules.

  • 301

    Multiple status codes

    Permanent (301), temporary (302), Not Found (404), and Gone (410). Choose the right response for each rule.

  • /.*/

    Exact & regex

    Match paths exactly or use regex with capture groups, with automatic trailing-slash matching. One pattern can handle many URLs.

  • 📈

    Hit analytics

    Per-redirect hit counts with 7-day and 30-day windows, plus a dashboard overview of totals, top redirects, and stale rules.

  • ⚖

    A/B testing

    Split traffic between two destination URLs with a weighted, cookie-sticky variant — hits tracked separately for each.

  • 🗓

    Scheduled backups

    Automatic CSV backups on a schedule, saved to disk and/or emailed — plus a periodic overview summary email.

  • ⚙

    Backoffice dashboard

    Search, filter, bulk activate/deactivate, export CSV, import CSV, and a 404 log for missed requests. Test a URL before saving.

  • 📦

    NuGet package

    Install via dotnet add package. App_Plugins and middleware are wired automatically.

  • 🗄

    Database storage

    Redirects live in a dedicated table, scoped per domain if needed. Migration runs on startup. No file edits.

Installation

Pick the option that fits your workflow.

NuGet (nuget.org)

Use this if the package is published on nuget.org.

dotnet add package BT.RedirectManager

Your own NuGet server (Docker)

Run BaGet in Docker, push the plugin, then add your feed and install in any project.

docker compose -f docker/docker-compose.yml up -d
./scripts/push-to-feed.sh

In your Umbraco project: add the feed to nuget.config, then dotnet add package BT.RedirectManager.

Local feed

Build the plugin repo, then point your project’s nuget.config at the build output folder.

dotnet build -c Release
# In your project: add feed path, then:
dotnet add package BT.RedirectManager

Usage

  1. Install the package and build your Umbraco project.
  2. Open the backoffice → Settings → Redirect Manager.
  3. Add a redirect: Old URL, New URL (for 301/302), status code, optional notes. Use regex if needed.
  4. Use filters and search, export/import CSV, or run “Test” on a path to see which rule matches.

Status codes

Each redirect can return a different HTTP response.

Code Name When to use
301 Permanent Redirect Page has permanently moved. Search engines transfer link equity to the new URL.
302 Temporary Redirect Page has temporarily moved. Use for A/B tests or short-term moves.
404 Not Found Return 404 for a specific path (e.g. deprecated URL that should not redirect).
410 Gone Resource is permanently gone. Tells crawlers to drop the URL from the index.

Changelog

Release notes for all versions.

1.6.0

  • Opt-in anonymous usage ping — a one-time consent prompt on first dashboard load (or the toggle on the Overview tab), so no data is ever sent without explicit permission.
  • Ping fires from a periodic background check and from the dashboard being opened, sharing one 24-hour-per-site throttle.

1.5.0

  • Fixed a critical crash: background flush services were corrupting Umbraco's ambient DB scope — rewritten to use standalone database connections.
  • Fixed CSV export being intercepted by Umbraco's backoffice router instead of downloading.
  • Trailing-slash matching: exact redirect rules now match regardless of a trailing slash.
  • Scheduled CSV backups (file and/or email) on a configurable interval.
  • A/B testing: weighted, cookie-sticky split between two destination URLs with separate hit tracking.
  • Dashboard overview panel — totals, top 10 redirects, stale-redirect list — plus CSV export and a periodic summary email.

1.4.0
